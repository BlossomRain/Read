# 电子学一-笔记模板

## 1. 目标

这份模板用于统一 `电子学一.md` 的后续写法，使章节编号、内容组织、图示风格、公式推导和语言密度保持一致。

---

## 2. 标题层级

章节层级固定如下：

- `### 1.x ...`：大节
- `#### 1.x.y ...`：小节
- `##### ...`：小节内部的内容块

要求：

- 目录和正文标题必须同步更新
- 小节标题必须带编号，不能只写英文标题

示例：

```md
### 1.4 DC and AC Voltage Charging C, Transient and Steady-State Solutions 电容的直流与交流充电、暂态与稳态解

#### 1.4.1 DC Voltage Charging C 直流对电容充电
```

---

## 3. 每个小节的推荐骨架

每个 `#### 1.x.y ...` 小节优先按下面顺序组织：

1. `> ◎ 核心：...`
2. `##### ◇ 直觉理解` 或 `##### ◇ 物理模型`
3. `##### ∎ 定义 / 推导 / 建立方程`
4. `##### ✓ 结论`
5. 必要时补：
   - `##### ✎ 我的理解`
   - `##### ⚠ 易错点`
   - `##### ∎ 时间常数 ...`
   - `##### ∎ 与前面内容的连接`

示例：

```md
#### 1.3.1 Capacitor 电容

> ◎ 核心：先用模型与等效的观点引入电容，再把 C=Q/V 与 C=εA/d 连起来。

##### ◇ 物理模型

...

##### ∎ 定义 / 推导

...

##### ✓ 结论

...
```

---

## 4. 行文风格

整体采用“紧凑讲义体”：

- 以中文为主，关键术语保留英文
- 少用“把 / 代入 / 可得 / 因此”单独占一行
- 公式前后的解释尽量接成连续句
- 保持页面紧凑，但不要压成大段文字墙
- 优先写“直觉 -> 公式 -> 电路 -> 结论”的顺序

不推荐：

- 过多空行
- 一句解释后立刻单独放一个很短的过渡词
- 把一个连续推导拆成太多零散步骤

---

## 5. 公式组织规则

公式尽量按“定义 -> 关系 -> 方程 -> 解”的顺序出现。

例如一阶 RC 电路：

1. 定义：
   $$
   C = \frac{Q}{V}
   $$

2. 电流关系：
   $$
   i = \frac{dQ}{dt} = C\frac{dv}{dt}
   $$

3. 电路方程：
   $$
   V = RC\frac{dv}{dt} + v
   $$

4. 一般解：
   $$
   v(t) = v_{tr}(t) + v_{ss}(t)
   $$

5. 特解 / 标准结果：
   $$
   v(t)=V(1-e^{-t/RC})
   $$

## 6. 图示规范

### 6.1 图的功能类型

常用图分为三类：

1. 直觉类比图
   - 例如水池、水管、水桶
   - 用于建立物理直觉

2. 模型 / 结构图
   - 例如平行板电容、麦克风结构
   - 用于解释对象本体

3. 等效电路 / 波形图
   - 例如戴维宁等效、RC 电路、时域响应
   - 用于正式分析

### 6.2 图的使用顺序

优先采用：

`类比图 -> 结构图 -> 等效图 -> 波形图`

要求：

- 物理结构不要直接硬接后级电路
- 如果要接后级，先做等效再接入
- 波形图优先横向并排，方便比较
- 每张波形图下方写清楚“谁对时间”

### 6.3 图文件命名

继续使用当前命名方式：

- `01-basic-...-diagram-01.tex`
- `01-basic-...-waveforms-01.tex`

目录规则：

- `image/电子学一/source/`：TeX 源文件
- `image/电子学一/figures/`：生成的 SVG 图

### 6.4 电路图绘制标准

后续所有电路图、例题图、SVG 手工图，统一遵守下面的规则。

1. 图的目标

- 优先像“课本电路图”而不是“海报说明图”
- 电路本体优先，说明文字只做辅助
- 一张图只表达一个主问题，不要同时塞太多解释层

2. 线条与布局

- 电路主线统一为深色细线，线宽保持一致
- 元件尺寸尽量统一，同类电阻、电容不要一张大一张小
- 节点用小实心圆，大小一致
- 画面尽量横向展开，便于和正文左右阅读顺序一致
- 图内留白要稳定，但不要把画面撑得过空

3. 字体与字号

- 全部使用同一字体族，优先 Times New Roman 或 TeX 默认数学风格
- 标题字号小于正文 H2/H3，不要做成海报式大标题
- 图中变量名可用斜体，例如 `R`、`C`、`v_o`
- 说明文字统一比变量名小一档
- 同一张图中不要混用三四套字号

4. 变量与标注规范

- 电路端点优先写简洁变量，如 `v_o`、`v_s`、`R_L`、`I_{dc}`
- 如果 SVG 手工绘制不稳定，可退化成 `vo`、`vs`、`RL`、`Idc`
- 同一批图必须使用同一套写法，不能一张写 `vo`、另一张写 `v_o(t)`
- 图中公式只放最必要的一行，长推导放正文

5. SVG 特别规则

- 不要在 SVG 里滥用 `tspan + baseline-shift` 做复杂下标
- 如果下标导致大小跳动，优先改成稳定写法，例如 `vo`、`vs`、`RL`
- XML 保留字符必须转义：
  - `<` 写成 `&lt;`
  - `>` 写成 `&gt;`
  - `<=` 写成 `&lt;=`
  - `>=` 写成 `&gt;=`
- 不要把临时板书式涂鸦直接搬进正式 SVG

6. 颜色使用

- 默认黑白或深灰单色
- 只有在“强调电流路径 / 噪声路径 / 对比关系”时才加第二颜色
- 第二颜色只服务于一个含义，不要一张图里红蓝绿各讲一件事
- 如果彩色标记会让人误以为是额外元件，宁可改成箭头加文字

7. 注释与说明

- 右侧说明尽量控制在 2 到 4 行
- 图内说明优先短语，不写整段句子
- 水桶类比、波形类比若需要补充说明，应与主电路拉开距离，避免重叠
- 说明文字不能压住电路主线、元件标签或节点

8. 类比图附加要求

- 类比图只能辅助理解，不能替代正式电路图
- 如果一张图同时放电路和水桶类比，两者之间要有明显分区
- 类比区不得与主电路区文字重叠

9. 最终检查清单

每次新增一张图后，至少检查下面几项：

- 是否一眼看得出主电路是什么
- 变量大小是否一致
- 下标、希腊字母、单位是否有突兀放大
- 是否存在 XML 非法字符
- 说明文字是否和电路或类比图区重叠
- 彩色箭头是否会被误解成元件

---

## 7. 波形图规范

波形图尽量满足：

- 同类信号排成一行
- 横轴统一为时间 `t`
- 每张图下方写标题
- 输入、输出、电流等最好同尺度风格

推荐标题格式：

- `input voltage--time / 输入电压-时间`
- `current--time / 电流-时间`
- `capacitor voltage--time / 电容电压-时间`

---

## 8. 一阶电路内容最低配置

凡是涉及一阶 RC / RL 电路，尽量都包含下面四项：

1. 微分方程
2. 瞬态解与稳态解
3. 时间常数
4. 波形直觉

例如应交代：

- 稳态：令 $\dfrac{d}{dt}=0$
- 瞬态：把输入源置零
- 时间常数：$\tau=RC$ 或 $\tau=L/R$
- 几个常见时间点：`1τ`、`3τ`、`5τ`

---

## 9. 中英混排规则

- 大标题保留中英对照
- 小标题保留中英对照
- 正文中文为主
- 核心术语保留英文，例如：
  - transient
  - steady-state
  - Thevenin equivalent
  - voltage amp

图下注释可以采用中英双写。

## 10. TeX 绘图注意事项

当前图示编译链以 `pdflatex` 为主，因此：

- 纯英文图最稳定
- 如果图中需要中文，需显式加入中文支持，例如 `CJKutf8`
- 不要默认直接把中文塞进 TeX 图里

最小示例：

```tex
\usepackage{CJKutf8}

\begin{document}
\begin{CJK*}{UTF8}{gbsn}
...
\end{CJK*}
\end{document}
```

## 11. 推荐写作流程

后续新增某一节时，建议按下面顺序进行：

1. 先根据课程页面补全标题与目录
2. 先写一句 `◎ 核心`
3. 决定是否需要类比图 / 结构图 / 等效图 / 波形图
4. 写直觉解释
5. 写关键定义与公式推导
6. 写电路方程或标准结果
7. 写结论与易错点
8. 最后检查版式是否紧凑

## 12. 小点分层模板

从 `1.5`、`1.6` 开始，后续每个 `#### x.x.x` 小节尽量按固定分层来写，避免把定义、推导、例题、应用和结论全部混在一起。

推荐顺序如下：

```md
#### x.x.x 标题

> ◎ 核心：一句话

##### ∎ 核心结论

---

##### ∎ 说明 / 推导

---

##### ◇ 例题
或
##### ◇ 应用

---

##### ✓ 小结
```

说明：

1. `∎ 核心结论`

- 只放这一小节最重要的 1 到 3 句
- 或者只放 1 条关键公式
- 让读者先知道“这一节到底要记什么”

2. `∎ 说明 / 推导`

- 只保留主线推理
- 同一条公式只在第一次出现时完整推导
- 后面若只是换场景使用，直接引用前面结论，不重复铺开

3. `◇ 例题`

- 适用于有已知条件、要代数值、最后要得到答案的内容
- 例题应当和前面的正文主线分开，不要嵌在推导中间

4. `◇ 应用`

- 适用于说明“这个电路为什么这样接”“这个元件在系统里扮演什么角色”
- 应用不一定需要完整数值计算
- 若只是解释用途，优先用 `◇ 应用`，不要硬写成 `◇ 例题`

5. `✓ 小结`

- 用 1 段或 2 到 3 条短句收束
- 不再重新讲长推理
- 只负责回收这一小节最该记住的判断

6. 分隔方式

- 小点之间统一使用 `---` 分割线做视觉隔离
- 不再把 `◇ 例题` 做成引用块或大色块
- 例题、应用保持普通小标题写法，只用分割线和标题层级区分
- `◎ 核心` 保留在节开头；正文内部主要依靠标题 + `---` 来分层

补充规则：

- 一个 `####` 下若已经有两个以上例题，通常应拆成两个小节
- 一个 `####` 下若同时出现两套完整推导，通常说明结构过满，应压缩成“首次推导 + 后文引用”
- 图若服务于例题，就挂在 `◇ 例题` 下；若服务于电路用途说明，就挂在 `◇ 应用` 下
