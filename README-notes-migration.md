# Read 仓库笔记迁移策略

这份文档配套 [README-notes-style.md](D:\read\Read\README-notes-style.md) 使用，说明旧内容如何逐步迁移到新规范。

---

## 1. 迁移原则

不做一次性全仓重构，原因很直接：

1. 仓库内容多，全面迁移成本高
2. 大量旧笔记已经可用，强改收益有限
3. 真正重要的是从现在开始不继续制造新混乱

因此采用：

- **新增内容立即遵守**
- **旧内容按需迁移**
- **迁移时只做必要整理**

---

## 2. 迁移优先级

建议按下面顺序处理。

### 优先级 1：新增主题

所有新建主题直接采用新规范：

- 主文档
- `assets/主题名/`
- 统一资源命名
- 统一引用方式

### 优先级 2：正在持续更新的旧主题

例如当前仍在学习中的课程或书籍，如：

- 电子学
- 电路学概论
- 线性代数

这些主题在继续写的时候，顺手迁移资源结构最划算。

### 优先级 3：资源混乱但价值高的主题

判断标准：

- 图片很多
- 文件名无语义
- 后续复习频繁
- 主题重要

### 优先级 4：已归档、低频访问主题

这类内容可以不动，维持现状即可。

---

## 3. 单篇文档迁移步骤

建议按最小改动原则处理。

### 第一步：确定是否迁移资源目录

如果该主题后续还会继续写，建议补齐：

```text
assets\主题名\
├─ figures
└─ source
```

如果暂时不想改目录名，也可以先保留旧的 `image/主题名/`，只在内部子目录上向新规范靠拢。

### 第二步：重命名新加入的资源

旧资源不用一次性全改，但新增资源从当天开始按新规则命名。

例如：

- 不再新增 `image-20220418164010124.png`
- 改为 `02-rc-step-response-plot-01.png`

### 第三步：统一文档内部引用风格

同一篇文档中，图片引用方式尽量保持一致。

### 第四步：补源文件

如果近期重画过正式图，尽量把源文件放到 `source/`。

### 第五步：必要时补文档头部信息

若旧文档信息太少，可补：

- 来源
- 时间
- 状态
- 标签

## 4. 推荐迁移方式

### 方式 A：只规范新增内容

适合大多数主题。

做法：

- 旧图片不动
- 新图片按新规则放
- 新内容按新结构写

优点：

- 成本最低
- 立刻见效

### 方式 B：边学边整理

适合仍在持续学习的主题。

做法：

- 每次新增一小节时，顺手整理相关图片和路径
- 逐渐把主题迁到新目录

优点：

- 不打断学习节奏
- 主题会自然变整洁

### 方式 C：专题重构

适合高价值、后续经常查阅的主题。

做法：

- 一次性整理目录
- 统一资源命名
- 修正引用路径
- 视情况优化正文结构

优点：

- 完成后最干净

缺点：

- 成本最高

## 6. 关于旧目录的处理

旧目录不需要马上统一改名。

例如现有：

```text
image\电子学一\
```

可以先继续保留，但后续逐步演进为：

```text
assets\电子学一\
```

迁移时机：

1. 该主题下一次大更新时
2. 该主题图片明显增多时
3. 该主题准备做系统整理时

---

## 7. 判断是否值得迁移

满足任意两条，就值得迁移：

- 后续还会继续写
- 图很多
- 经常复习
- 资源命名混乱
- 需要保存源文件
- 已经开始出现查找困难

---

## 8. 最终目标

迁移不是为了把旧内容全部“洗一遍”，而是为了逐步达到下面这个状态：

1. 新内容从创建起就是整洁的
2. 高价值主题可维护、可查找、可复用
3. 仓库结构随着时间推移越来越稳定，而不是越来越乱

---

## 9. 建议的执行节奏

最现实的节奏是：

1. 先定规范
2. 新笔记立即执行
3. 选一个区域试点
4. 持续学习时增量迁移
5. 只对高价值主题做专题重构

这样成本最低，也最容易长期坚持。
