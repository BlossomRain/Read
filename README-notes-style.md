# Read 仓库笔记规范

这份规范适用于整个 [D:\read\Read](D:\read\Read) 仓库。

目标只有三个：

1. 新增笔记时结构一致，降低维护成本。
2. 图片、附件、源文件有固定位置，避免后期混乱。
3. 不强行统一所有学科的正文写法，只统一最值得统一的部分。

---

## 1. 适用范围

本规范适用于仓库中的所有主题目录，包括但不限于：

- `01-Java`
- `02-数据库`
- `03-Python`
- `07-Linux`
- `09-数学-物理-电子`
- `11-经济学-人文`

---

## 2. 总体原则

### 2.1 一主题一主文档

默认采用：

- `1 个主题 = 1 个主 Markdown 文档`

例如：

- `电子学一.md`
- `电路学概论.md`
- `深入理解Java虚拟机.md`

### 2.2 一主题一资源目录

每个主题原则上配套一个资源目录，统一放图片、附件和源文件。

推荐结构：

```text
主题目录\
├─ 主题.md
└─ assets\
   └─ 主题名\
      ├─ figures
      └─ source
```

说明：

- `figures/`：所有最终插入笔记的图，包括概念图、结构图、电路图、函数图、仿真图、截图
- `source/`：可编辑源文件和中间材料，如 `drawio`、`tex`、仿真工程、原始表格、转换脚本等

如果旧目录已经在使用 `image/主题名/`，可以暂时保留，不强制立即改名；新主题优先使用 `assets/主题名/`。

---

## 3. 文件与目录命名

### 3.1 主文档命名

主文档可以继续沿用当前仓库习惯，使用中文主题名：

- `电子学一.md`
- `线性代数学习笔记.md`
- `Spring实战.md`

### 3.2 资源文件命名

资源文件统一使用英文短名，避免使用时间戳或无语义名称。

推荐格式：

```text
[章节]-[主题]-[类型]-[序号].[扩展名]
```

示例：

- `01-jvm-memory-diagram-01.svg`
- `02-btree-search-figure-01.svg`
- `03-rc-step-response-plot-01.svg`
- `04-labor-contract-flow-diagram-01.svg`

### 3.3 类型字段建议

建议统一使用完整单词：

- `figure`
- `diagram`
- `plot`
- `photo`

说明：

- 最终图片目录统一放在 `figures/`
- 图片具体属于电路图、曲线图还是普通示意图，通过文件名中的 `diagram / plot / figure` 区分

---

## 4. 图片与附件格式

### 4.1 推荐格式

- `svg`：默认格式，适用于结构图、流程图、关系图、示意图、电路图、函数图
- `png`：截图、仿真软件直接导出的图、无法稳定输出为矢量图的位图内容
- `jpg`：照片类材料

### 4.2 选择原则

1. 默认使用 `svg`
2. 截图和光栅类内容使用 `png`
3. 照片类使用 `jpg`
4. 能直接用 Markdown 和 LaTeX 表达的内容，尽量不要做成图片

---

## 5. 源文件保留规则

正式整理后的图，原则上应保留可编辑源文件。

统一放在：

```text
assets/主题名/source/
```

常见示例：

- `01-basic-thevenin-equivalent.drawio`
- `02-rc-step-response.asc`
- `build-tex-figure.ps1`
- `03-function-plot.xlsx`

规则：

1. 截图类资源可以没有源文件
2. 自己绘制的正式图，尽量保留源文件
3. 引用外部原始资料时，放入 `source/` 中单独整理，或保留在旧目录中逐步迁移
4. 中间编译产物如 `.aux`、`.log`、`.pdf` 原则上不保留

---

## 6. Markdown 引用规则

统一使用相对路径引用资源。

示例：

```md
![Thevenin Equivalent](./assets/电子学一/figures/01-basic-thevenin-equivalent-diagram-01.svg)
```

如果主题仍在使用旧结构：

```md
![Water Analogy](./image/电子学一/figures/01-basic-water-analogy-figure-01.png)
```

规则：

1. 同一篇文档内部引用方式保持一致
2. 不混用多种路径风格
3. 不使用无语义文件名

---

## 7. 文档头部最小模板

所有新笔记建议至少包含以下头部信息：

```md
# 标题

- [ ] 来源:
- [ ] 时间:
- [ ] 状态:
- [ ] 标签:

---
```

说明：

- `来源`：书籍、课程、视频、论文、项目文档等
- `时间`：首次记录或本轮整理日期
- `状态`：进行中 / 已完成 / 待复习
- `标签`：便于后续分类检索

---

## 8. 正文结构策略

仓库级别不强制所有文章使用同一个大纲。

原因：

- 编程类、数学类、物理类、人文类的最佳写法不同
- 统一过度会增加写作负担，反而降低执行率

仓库只要求：

1. 标题层级清晰
2. 同一篇文档内部风格尽量一致
3. 优先记录自己的理解，而不是机械搬运原文

### 8.1 课程讲义体（正文 + 附录）

适用于内容多、推导长的**课程笔记**（如 `电子学一.md`）。已在 [电子学一-笔记模板.md](09-数学-物理-电子/电子/电子学/电子学一-笔记模板.md) 落地，其他课程可照搬。

**分工：**

| 位置 | 写什么 |
|------|--------|
| **正文** | `◎ 核心`、关键公式与结论、图、例题的**结果与套路**、易错点 |
| **文末附录** | 完整求导/证明、复平面与欧拉推导、微分方程解法等**过程** |

**文首一行（建议）：**

```md
正文只保留结论与用法；长推导见文末 [附录](#附录)，文中以「见 [附录 X](#…)」引用。
```

**正文引用：**

```md
（求导见 [附录 A](#附录-a-最大功率传输定理)）
```

**附录条目：**

- 标题：`### 附录 A 简短标题`（字母 + 中文，锚点自动生成）
- 每条附录开头写：**对应正文：** 回链到 `#### 1.x.y`
- 目录中列出附录子项，与正文章节并列

**何时进附录：** 超过约 5 行的连贯推导、首次出现的完整证明、复数/相量基础等「工具性」推理；正文只留一句结论 + 链接。

**何时留正文：** 本节必须当场记住的式子、一步能看完的代入、与图直接对应的 KVL/KCL。

**多章拆分：** 单章过长时可拆为 `主题一.md`、`主题一第二章.md`；主文档目录链到分章文件，章末用「**下一章：**」链接。

## 9. 领域模板建议

### 9.1 技术 / 编程类

适用：Java、Python、数据库、Linux、前端等

推荐结构：

- 概念
- 原理
- 关键机制
- 示例 / 代码
- 易错点
- 实践建议

### 9.2 数学类

推荐结构：

- 直觉
- 定义
- 定理 / 性质
- 推导 / 证明
- 例题
- 易错点

### 9.3 物理 / 电子类

推荐结构：

- 对象 / 场景
- 基本规律
- 数学表达
- 图示 / 电路
- 典型例题
- 直觉理解
- 易错点

**课程讲义体（推荐）：** 见 [8.1](#81-课程讲义体正文--附录)；符号块用 `◎ / ◇ / ∎ / ✓ / ⚠`，小节收束优先 `✓ 小结`；长推导进附录。细则见 [09-数学-物理-电子/README-note-template.md](09-数学-物理-电子/README-note-template.md) 与 [电子学一-笔记模板.md](09-数学-物理-电子/电子/电子学/电子学一-笔记模板.md)。

### 9.4 人文 / 法律 / 经济类

推荐结构：

- 核心观点
- 关键概念
- 结构框架
- 典型案例
- 我的理解
- 待验证问题

## 10. 执行策略

### 10.1 对新笔记

新笔记从创建开始遵守本规范。

### 10.2 对旧笔记

旧笔记不强制一次性重构，采用增量迁移：

1. 有新增内容时顺手整理
2. 有新增图片时优先按新规则存放
3. 重要主题可单独安排重构

### 10.3 优先统一的内容

优先级从高到低：

1. 资源目录位置
2. 资源命名
3. Markdown 引用路径
4. 源文件保留
5. 正文结构优化（新课程笔记优先采用「正文 + 附录」）

### 10.4 规范文档索引

| 文档 | 用途 |
|------|------|
| [README-notes-style.md](README-notes-style.md) | 全仓笔记与资源规范 |
| [09-数学-物理-电子/README-note-template.md](09-数学-物理-电子/README-note-template.md) | 数理化章节与符号 |
| [09-数学-物理-电子/电子/电子学/电子学一-笔记模板.md](09-数学-物理-电子/电子/电子学/电子学一-笔记模板.md) | 电子学课程讲义体、作图、附录细则 |

## 11. 不建议的做法

- 图片名使用时间戳，如 `1774856147457.png`
- 正式图没有源文件
- 同一主题中图片散落在多个无规则目录
- 把公式、表格、代码能直接表达的内容全部做成截图
- 为了统一而强行让所有学科使用同一种正文模板

---

## 12. 结论

这个规范的重点不是“把所有笔记写得一样”，而是：

- 让资源组织方式一致
- 让新内容从现在开始可维护
- 给不同学科保留合适的表达空间

执行上采用“新内容先规范，旧内容渐进迁移”的策略。
